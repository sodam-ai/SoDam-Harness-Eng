# SoDamHarness (소담하네스) — 완전 초보자를 위한 AI 안전벨트

> **AI(Claude Code)로 코딩할 때, 실수로 큰 사고가 나지 않게 막아 주는 "안전벨트"** 입니다.
> 개발·AI·컴퓨터가 처음이어도 **그대로 따라 하면** 됩니다. 이 문서 하나에 설치부터 사용법·구조·보안·문제 해결·라이선스까지 **전부** 들어 있습니다.
>
> ⚠️ **가장 먼저 알아 둘 것 (정직한 약속):** 이 도구는 **흔한 위험을 막아 주는 "안전벨트"** 이지, 모든 사고를 막는 **"방탄막"이 아닙니다.** "100% 안전"은 **세상에 없습니다.** 그래도 안전벨트는 사고 피해를 크게 줄여 줍니다.

## 0. 이게 뭔가요? (1분 이해)

### AI와 내 컴퓨터 파일의 관계

AI에게 "이거 해 줘"라고 시키면, AI는 **내 컴퓨터의 파일을 직접** 만들고·고치고·지웁니다. 마치 내가 직접 파일을 다루는 것과 같습니다. 편리하지만, 문제가 하나 있습니다.

**AI도 실수를 합니다.** 예를 들어:
- "이 파일 정리해 줘" 했는데 **잘못된 파일을 지워 버리는** 경우
- "폴더 좀 정리해 줘" 했는데 **중요한 폴더 전체를 삭제**하는 경우
- "코드 수정해 줘" 했는데 **기존 내용이 통째로 바뀌는** 경우

이런 일이 벌어지면 **되돌리기가 매우 어렵습니다.**

### SoDamHarness가 하는 일

SoDamHarness는 AI와 내 파일 사이에 서서 **문지기** 역할을 합니다.

- 🛑 **아주 위험한 일**(폴더 통째 삭제, 시스템 폴더 삭제 등)은 **아예 막습니다.**
- 💾 **되돌리기 어려운 일**(파일 삭제·덮어쓰기·이동) 전에는 **자동으로 파일을 백업**하고 **"정말 할까요?"** 라고 물어봅니다.
- ↩️ 실수했어도 **백업에서 되살릴 수 있습니다.**
- 🔒 비밀번호·토큰·인증 파일은 **절대 건드리지 않고, 백업에도 저장하지 않습니다.**
- 🗣️ 모든 안내를 **쉬운 한국어**로 해 줍니다.

> **자동차 안전벨트처럼:** 안전벨트가 있다고 운전을 거칠게 해도 된다는 뜻은 아닙니다. 하지만 사고가 났을 때 **피해를 훨씬 줄여** 줍니다.

## 0-1. 어떻게 작동하나요? (내부 구조·아키텍처)

> 💡 이 섹션은 "어떻게 동작하는지 원리가 궁금한 분"을 위한 것입니다. 당장 설치만 하고 싶으면 **1번으로 건너뛰어도** 됩니다.

### 동작 흐름

```
[사용자] → "파일 지워 줘" → [Claude Code(AI)]
                                     │
                                     ▼
                        [SoDamHarness 안전벨트 감시]
                                     │
          ┌──────────────────────────┼──────────────────────────┐
          ▼                          ▼                           ▼
     안전한 일                  위험한 일                 아주 위험한 일
  (파일 만들기 등)           (파일 삭제 등)            (폴더 통째 삭제 등)
          │                          │                           │
          ▼                          ▼                           ▼
     그냥 실행           백업 저장 + 확인 요청              즉시 차단
                        OK하면 실행 / 아니면 취소          (실행 안 함)
```

### 3등급 분류표

AI가 하려는 일을 안전벨트가 자동으로 3가지로 나눕니다.

| 등급 | 이름 | 어떤 일 | 안전벨트 반응 |
|---|---|---|---|
| 1등급 | safe (안전) | 파일 만들기, 파일 읽기, 일반 코드 편집, 새 폴더 만들기 | 그냥 실행 ✅ |
| 2등급 | risky (위험) | 파일 삭제, 파일 덮어쓰기, 파일 **이동**(`mv`/`move`/`Move-Item`), 배포 명령, 외부 전송 | 백업 💾 → 확인 요청 ⚠️ → 실행 or 취소 |
| 3등급 | catastrophic (재앙) | 폴더 통째 삭제(`rm -rf`), 시스템 폴더 삭제, Windows/Program Files 삭제 | 즉시 차단 🛑 (실행 불가) |

### 어떤 파일들이 이 일을 하나요?

| 파일 이름 | 별명 | 하는 일 |
|---|---|---|
| `hooks/guard.mjs` | 경비원 | AI가 도구를 쓰기 **전에** 실행돼서 위험도를 판단하고 막거나 허용 |
| `hooks/backup.mjs` | 백업 담당 | 위험한 작업 전 파일을 `~/.sodamharness/backups/`에 자동 저장 |
| `hooks/whitelist.mjs` | 허가 목록 | `/sodam-harness:trust`로 "이건 안 물어봐도 돼"라고 등록한 목록 관리 |
| `hooks/activity.mjs` | 일지 기록원 | AI가 한 일을 `~/.sodamharness/activity.log`에 기록 (파일명·시각만, 비밀 마스킹) |
| `hooks/safety-rules.json` | 규칙집 | 위험 패턴 목록 (guard.mjs가 이 파일을 읽어서 판단) |
| `hooks/profile.mjs` | 맞춤 설정 담당 | `/sodam-harness:wizard`가 고른 확인 빈도(L1/L2/L3)를 `~/.sodamharness/profile.json`에 저장 — guard.mjs가 이 값을 읽어 **ask 빈도만** 조정(차단·백업은 무관하게 항상 그대로) |
| `commands/` | 명령 모음 | 사용자가 `/sodam-harness:...`를 치면 실행되는 7개 명령 |

> **비유로 이해하기:** guard.mjs는 건물 앞 경비원, backup.mjs는 금고 담당 직원, whitelist.mjs는 VIP 명단, activity.mjs는 방문자 출입 기록부, profile.mjs는 "이 손님은 얼마나 자주 신분 확인을 하길 원하는지" 적어 둔 손님 카드입니다. safety-rules.json은 경비원이 들고 다니는 "위험 목록 수첩"입니다.

## 1. 사전 준비물 (필요한 프로그램)

딱 **2가지**만 있으면 됩니다.

### (1) Node.js — 안전벨트 엔진

**Node.js가 뭔가요?** 웹사이트·앱·프로그램을 만들 때 쓰는 무료 도구입니다. SoDamHarness의 안전 기능은 Node.js로 만들어져 있어서 반드시 필요합니다. (비용: 완전 무료)

**이미 있는지 확인하는 방법 (윈도우):**

1. 키보드에서 **⊞ 윈도우키** 를 누릅니다.
2. `powershell` 이라고 입력합니다.
3. **Windows PowerShell** 이라는 항목을 클릭합니다.
4. 검은 창이 열리면, 아래를 입력하고 **Enter**:
   ```
   node --version
   ```
5. `v18.19.0` 처럼 **v18 이상** 숫자가 나오면 이미 설치됨 (예: `v22.19.0`).
   `'node'은(는) 내부 또는 외부 명령...` 이라고 나오면 없는 것.

**없으면 설치하는 방법 (윈도우):**

1. 웹브라우저(크롬·엣지 등)를 엽니다.
2. 주소창에 `https://nodejs.org` 를 입력하고 Enter.
3. 초록색 **"LTS"** 버튼을 클릭합니다. (LTS = Long Term Support = 안정 버전. "Current" 말고 반드시 **"LTS"** 를 선택하세요.)
4. 내려받기가 끝나면 내려받은 파일(`node-v**.msi`)을 **더블클릭**합니다.
5. 설치 창이 열리면 **"다음(Next)"** 버튼만 계속 누릅니다. (설정은 바꾸지 않아도 됩니다.)
6. "설치(Install)" → 설치 완료 → "마침(Finish)".
7. **컴퓨터를 껐다 켭니다** (또는 PowerShell 창을 닫고 새로 엽니다).
8. 위 확인 방법으로 `v18` 이상이 나오면 성공.

**이미 있는지 확인하는 방법 (맥):**

1. 키보드 **Cmd + Space** → `터미널` 입력 → **터미널** 클릭.
2. 아래를 입력하고 **Return**:
   ```
   node --version
   ```
3. `v18` 이상이면 이미 설치됨.

**없으면 설치 (맥):** `https://nodejs.org` 에서 **LTS** 버튼 클릭 → `.pkg` 파일을 더블클릭해서 설치.

> ⚠️ **맥 주의:** SoDamHarness는 현재 윈도우에서만 실제 검증했습니다. 맥에서도 동작하도록 만들었지만 미검증입니다.

### (2) Claude Code — AI 코딩 도구 (이 안전벨트가 붙는 곳)

**Claude Code가 뭔가요?** Anthropic(앤트로픽)이라는 회사가 만든 **AI 코딩 도우미**입니다. 터미널(검은 명령창)에서 실행하며, "이 코드 고쳐 줘", "파일 만들어 줘" 같은 자연어 지시를 이해하고 실제로 실행합니다. SoDamHarness는 Claude Code **위에** 설치되는 안전벨트 플러그인입니다.

이미 이 글을 Claude Code에서 보고 있다면 **설치되어 있는 것**입니다.

**비용 안내:**
- Node.js: **완전 무료**
- Claude Code: Anthropic에서 제공. **무료 플랜**과 **유료 플랜**이 있습니다. 정확한 요금은 공식 사이트 `https://claude.ai` 에서 확인하세요. (본 도구는 Anthropic과 공식 제휴 관계가 없으며, 요금 정보는 변경될 수 있습니다.)

> 💡 **"검은 명령창(터미널)"이 뭔가요?** 컴퓨터에 글자로 명령을 내리는 창입니다.
> **여는 법(윈도우):** 키보드 **⊞ 윈도우키** → `powershell` 입력 → **Windows PowerShell** 클릭.
> **여는 법(맥):** **Cmd + Space** → `터미널` 입력 → 클릭.

## 1-1. 다운로드 방법

SoDamHarness 파일을 내 컴퓨터에 가져오는 방법 3가지입니다. **지금 상황에 맞는 방법 하나**를 선택하세요.

---

### 방법 A — GitHub에서 ZIP으로 내려받기 (공개 후 / 일반 사용자 추천)

> ⚠️ **현재 기준:** 아직 GitHub에 공개되지 않아 이 방법은 사용할 수 없습니다. 공개된 후에 이 방법을 쓰세요.

GitHub는 프로그램 파일을 올려두는 인터넷 저장소입니다. ZIP 파일로 한 번에 내려받을 수 있습니다.

1. 웹브라우저에서 `https://github.com/sodam-ai/SoDam-Harness-Eng` 접속.
2. 화면 오른쪽 초록색 **"Code"** 버튼을 클릭합니다.
3. 드롭다운 메뉴에서 **"Download ZIP"** 을 클릭합니다.
4. ZIP 파일이 내 컴퓨터 "다운로드" 폴더에 저장됩니다.
5. ZIP 파일을 **우클릭** → "모두 압축 풀기(Extract All)" → 원하는 폴더에 압축 해제.
   - **경로에 한글이 없는 곳을 추천**합니다. 예: `C:\SoDam-Harness-Eng\`
6. 압축 해제된 폴더의 **전체 경로**를 메모해 둡니다. (설치할 때 필요)

---

### 방법 B — 개발자·지인에게 폴더째 받은 경우 (현재 방법)

> ✅ **지금은 이 방법을 쓰세요.**

개발자나 지인에게 폴더째 받았거나, USB·공유 폴더로 받은 경우입니다.

1. 받은 폴더를 **내 컴퓨터에 복사**합니다.
   - 예: `D:\SoDam-Harness-Eng\` 또는 `C:\Users\내이름\SoDam-Harness-Eng\`
   - **경로에 한글이 없는 곳을 추천**합니다.
2. 폴더 안에 `plugin.json`, `hooks/`, `commands/` 폴더가 있으면 정상입니다.
3. 이 폴더의 **전체 경로**를 메모해 둡니다. (설치할 때 붙여넣어야 합니다.)

**전체 경로 확인 방법 (윈도우):**
- 탐색기(파일 탐색기)에서 폴더를 엽니다.
- 위쪽 주소창(경로 표시 부분)을 클릭하면 전체 경로가 텍스트로 나타납니다.
- **Ctrl+A** (전체 선택) → **Ctrl+C** (복사)합니다.

## 1-2. Claude Code 설치 방법

> 💡 이미 Claude Code를 쓰고 있다면 이 섹션은 건너뛰어도 됩니다.

### Claude Code가 뭔가요?

Claude Code는 Anthropic(앤트로픽)이 만든 **AI 코딩 도우미**입니다. 터미널(검은 명령창)에서 실행하며, "이 코드 고쳐 줘", "파일 만들어 줘" 같은 자연어 지시를 이해하고 실제로 실행합니다. SoDamHarness는 Claude Code 위에 설치되는 플러그인이라 **Claude Code 없이는 동작하지 않습니다.**

### 구독·요금 안내

Claude Code는 Anthropic의 API 사용량에 따라 요금이 발생합니다. 정확한 요금 정책은 공식 사이트에서 확인하세요:
- 공식 사이트: `https://claude.ai`
- Claude Code 안내: `https://claude.ai/claude-code`

> ⚠️ **안내:** 본 도구(SoDamHarness)는 Anthropic과 공식 제휴 관계가 없습니다. 요금·플랜 정보는 언제든 바뀔 수 있으니 반드시 공식 사이트에서 최신 정보를 확인하세요.

### Claude Code 설치 단계

**사전 조건:** Node.js가 먼저 설치되어 있어야 합니다 (위 1번 참고).

1. 터미널(검은 명령창)을 엽니다.
   - 윈도우: **⊞ 윈도우키** → `powershell` → **Windows PowerShell** 클릭.
   - 맥: **Cmd + Space** → `터미널` 입력 → **터미널** 클릭.

2. 아래를 입력하고 **Enter**:
   ```
   npm install -g @anthropic-ai/claude-code
   ```
   - `npm`은 Node.js와 함께 설치되는 프로그램 설치 도구입니다.

3. 설치가 끝나면 아래를 입력하고 **Enter**:
   ```
   claude
   ```

4. 처음 실행하면 로그인·약관 동의 안내가 나옵니다. 화면 지시에 따라 진행합니다.

## 4. 사용·작동 방법 (안전벨트가 언제 어떻게 작동하나)

평소엔 **평소처럼** AI에게 일을 시키면 됩니다. 위험한 순간에만 안전벨트가 나섭니다.

### 안전 동작 상세 표

| AI가 하려는 일 | 구체적인 예 | 안전벨트 반응 |
|---|---|---|
| 파일 **만들기** | "readme.txt 만들어 줘" | 그냥 진행 ✅ |
| 파일 **읽기** | "이 파일 내용 보여 줘" | 그냥 진행 ✅ |
| 일반 **편집** | "이 코드 고쳐 줘" | 그냥 진행 ✅ |
| 새 **폴더 만들기** | "src 폴더 만들어 줘" | 그냥 진행 ✅ |
| 파일 **삭제** | "이 파일 지워 줘" | 💾 백업 → ⚠️ 확인 요청 |
| 파일 **덮어쓰기** | "파일 내용 통째로 바꿔 줘" | 💾 백업 → ⚠️ 확인 요청 |
| 파일 **이동** | "이 파일을 다른 폴더로 옮겨 줘" (`mv`/`move`/`Move-Item`) | 💾 백업 → ⚠️ 확인 요청 |
| 파일 **이름 바꾸기** | "이 파일 이름 바꿔 줘" (`ren`/`rename`/`Rename-Item`) | 💾 백업 → ⚠️ 확인 요청 |
| 복사·이동 때 **덮어써질 기존 파일** | 옮기려는 폴더에 같은 이름 파일이 이미 있음 (있는 줄 몰랐던 경우 포함) | 💾 그 파일도 함께 백업 → ⚠️ 확인 요청 |
| **배포** 명령 | "서버에 올려 줘" | ⚠️ 확인 요청 |
| 파일 **외부 업로드** | `curl`/`wget`/`scp`로 파일 전송 (비밀키 유출 방지) | ⚠️ 확인 요청 |
| **대량 삭제·초기화** | `find … -delete`, `truncate -s 0`(파일 0-초기화) | ⚠️ 확인 요청 (홈·폴더 대상이면 🛑) |
| **폴더 통째 삭제** | "이 프로젝트 폴더 지워 줘" | 🛑 차단 (실행 불가) |
| **시스템 폴더** 삭제 | Windows, Program Files 삭제 | 🛑 차단 (실행 불가) |
| `rm -rf` 등 | 강제 재귀 삭제 명령 | 🛑 차단 (실행 불가) |
| 비밀번호·토큰·인증 파일 | `.env`, `auth.json`, `*.pem` 등 | 🔒 접근 안 함·백업 제외 |
| **커밋(commit)에 비밀파일이 섞임** | `git commit` 직전, 스테이징된 파일 중 `.env` 등 비밀파일로 보이는 이름이 있음 | ⚠️ 확인 요청 (파일 **이름만** 확인, 내용은 절대 안 봄) |

> 📌 **파일 이동(`mv`/`move`/`Move-Item`)도 삭제와 똑같이 백업+확인을 거칩니다.** 2026-07-27 실사용 중 "이동은 원본이 그대로 사라지는데도 확인 없이 통과되는" 안전 구멍을 발견해 막았습니다. **이름 바꾸기**와 **복사·이동으로 덮어써지는 기존 파일**도 같은 종류의 구멍이라 2026-08-02에 함께 막았고, **git commit 비밀파일 검사**는 2026-08-02에 새로 추가했습니다 (자세한 내용: 10-1번 업데이트 요약).

### 백업은 어디에?

위험한 작업 전 파일은 자동으로 `~/.sodamharness/backups/` 폴더에 저장됩니다.
- 윈도우 예: `C:\Users\내이름\.sodamharness\backups\`
- 이 폴더에 비밀번호·토큰은 절대 저장하지 않습니다.
- 실수로 지웠다면 **`/sodam-harness:undo`** 로 되살립니다.

### 자동 승인 모드 주의사항

Claude Code의 "자동 승인(YOLO)" 모드를 켜면 "정말 할까요?" 확인 창이 생략될 수 있습니다. **그래도 백업은 됩니다.** 하지만 확인 창 없이 작업이 진행되므로, 위험 작업이 많다면 **자동 승인 모드를 쓰지 않는 것**을 권장합니다.

## 5-1. 보안·데이터 흐름

> 💡 "내 파일이 외부로 나가지 않나?", "어떤 데이터가 저장되나?" 궁금한 분을 위한 섹션입니다.

### 완전 로컬 동작 (인터넷 없음)

SoDamHarness의 안전 기능은 **설치 이후 인터넷이 전혀 필요 없습니다.** 모든 동작이 내 컴퓨터 안에서만 일어납니다.

- 경비원(guard.mjs): 내 컴퓨터 안에서 규칙집(safety-rules.json)을 읽어 판단
- 백업(backup.mjs): 내 컴퓨터의 `.sodamharness/backups/` 폴더에만 저장
- 활동 기록(activity.mjs): 내 컴퓨터의 `.sodamharness/activity.log`에만 기록
- 어떤 데이터도 외부 서버로 전송하지 않음

### 저장되는 것 vs 저장되지 않는 것

| 항목 | 저장 여부 | 저장 위치 |
|---|---|---|
| 작업한 파일의 **내용 백업** (위험 작업 전) | ✅ 저장됨 | `~/.sodamharness/backups/` (내 컴퓨터만) |
| 작업 **파일 이름·시각** (활동 로그) | ✅ 저장됨 | `~/.sodamharness/activity.log` (내 컴퓨터만) |
| 파일 **내용** (활동 로그에) | ❌ 저장 안 됨 | — |
| **비밀번호·토큰·인증서** | ❌ 절대 저장 안 됨 | — |
| 사용자 이름·이메일 등 **개인정보** | ❌ 수집 안 함 | — |
| **외부 서버** 전송 | ❌ 없음 | — |

### 데이터 흐름 다이어그램

```
[AI 작업 요청]
       │
       ▼
[guard.mjs — 위험도 판단] ← [safety-rules.json (규칙집)]
       │
       ├─ safe(안전) ─────────────────────────────────→ 그냥 실행 ✅
       │
       ├─ risky(위험) ──→ [backup.mjs — 백업 저장]  ──→ [사용자 확인]
       │                   (내 컴퓨터에만 저장)           │         │
       │                                           예  →  실행 ✅
       │                                           아니오 → 취소 ↩️
       │
       └─ catastrophic(재앙) ──────────────────────────→ 즉시 거부 🛑
       │
       ▼
[activity.mjs — 기록] → activity.log (파일명·시각만, 내용 없음)
```

### 절대 건드리지 않는 파일 목록

아래 파일들은 안전벨트가 절대 읽거나 백업하거나 수정하지 않습니다:

- `.env`, `.env.*` (환경 변수 파일)
- `auth.json`, `credentials.json`, `token.json` (인증 파일)
- `*.pem`, `*.key`, `*.crt` (인증서·키 파일)
- 윈도우: `%AppData%\Microsoft\Credentials\` (시스템 자격증명)
- 기타 민감 경로로 판단되는 파일

> **왜 이렇게 하나요?** 실수로 백업 파일에 비밀번호가 포함되는 사고를 원천 차단하기 위해서입니다.

### 개인정보 관련

SoDamHarness는 **개인정보를 수집하지 않습니다.** 이름, 이메일, 사용 통계, 오류 보고 등 어떤 데이터도 외부로 나가지 않습니다.

### 백업 폴더 접근 권한 (Windows)
- 백업 폴더(`~/.sodamharness/backups/`)는 따로 잠그지 않고, **Windows가 기본으로 정하는 내 계정 폴더 권한**에 그대로 의존합니다. 보통 이 컴퓨터의 다른 사용자 계정은 내 사용자 폴더 안을 볼 수 없습니다(윈도우 기본 동작).
- 여러 사람이 **같은 계정**을 함께 쓰는 컴퓨터라면, 백업 폴더도 그 계정을 쓰는 사람 모두가 볼 수 있다는 점을 알아 두세요.

### 비공식 "AI 안전" 도구 주의
- "AI 안전"을 내세우면서 **로그인 토큰·비밀번호를 요구하는 비공식 도구는 특히 조심하세요.** 실제로 그런 방식으로 로그인 정보를 몰래 빼간 사고가 있었습니다.
- SoDamHarness는 **어떤 토큰·비밀번호도 요구하지도, 저장하지도 않습니다.** 어떤 도구든 로그인 정보를 달라고 하면 일단 의심하세요.

## 5-2. (선택) Codex(코덱스)에서도 쓰기

> ⚠️ **정직한 한계 먼저:** SoDamHarness의 **자동 차단·백업·되돌리기(undo)는 Claude Code 전용**이라 **Codex에선 동작하지 않습니다.** Codex에선 **Codex 자체 기능(승인 창 + 샌드박스)** 으로 대신하며, 보호 방식·강도가 다릅니다. ("100% 안전"은 없습니다.)

Codex를 함께 쓰는 분을 위한 보조 설정입니다.

1. **쉬운 말투** — 플러그인 폴더의 **`AGENTS.md`** 를 Codex로 작업할 프로젝트 폴더에 **복사**합니다. (기존 `AGENTS.md`가 있으면 덮어쓰지 말고 내용을 **추가·병합**.)

2. **보수적 안전 설정** — 템플릿 **`codex/config.toml.example`** 의 두 줄(`approval_policy`, `sandbox_mode`)을 **`~/.codex/config.toml`** 에 **추가·병합**합니다.
   - ⚠️ 기존 설정 **덮어쓰기 금지.**
   - ⚠️ **`~/.codex/auth.json`(로그인 토큰)은 절대 건드리지 않기.**
   - ⚠️ 적용은 본인이 직접.
   - 값 이름은 Codex 버전마다 다를 수 있음 → 공식 문서: `https://developers.openai.com/codex/config-reference`

3. **확인** — Codex를 다시 켜고 버려도 되는 빈 폴더에서 위험 작업을 시켜 **승인 창이 뜨는지** 확인합니다.

4. 자세한 단계는 플러그인 폴더의 **`codex/CODEX_SETUP.md`** 에도 있습니다. 막히면 (Claude Code에서) **"코덱스 안전 설정 도와줘"** 라고 하세요.

## 6. 명령어 (언제 무엇을 쓰나)

입력칸에 **`/sodam-harness:`** 까지 치면 아래가 자동완성으로 뜹니다. 모두 **Claude Code 전용**입니다.

---

### `/sodam-harness:install` — 설치 확인 + 시작 안내

**언제 쓰나:** 처음 설치한 직후, 또는 "잘 설치됐나?" 확인할 때.

**무슨 일이 일어나나:**
- 안전벨트가 제대로 켜져 있는지 확인
- 처음 쓰는 분을 위한 시작 안내

**예시 출력:**
```
✅ SoDamHarness 안전벨트가 켜져 있습니다.
💡 빠른 시작: 버려도 되는 폴더에서 AI에게 파일 삭제를 시켜 보세요.
```

---

### `/sodam-harness:status` — 현재 상태 + 자가진단

**언제 쓰나:** "안전벨트가 지금 잘 작동하나?" 확인하고 싶을 때.

**무슨 일이 일어나나:**
- 훅(경비원)이 켜져 있는지 점검
- 백업 폴더 상태 확인
- "다음에 할 일" 안내

---

### `/sodam-harness:fix` — 문제 해결 안내

**언제 쓰나:** 뭔가 이상할 때, 명령이 안 먹힐 때, 안전벨트가 안 작동하는 것 같을 때.

**무슨 일이 일어나나:**
- 증상을 물어봄 → 원인과 해결 방법 안내
- 재설치·재시작 안내도 포함

---

### `/sodam-harness:undo` — 실수 되돌리기

**언제 쓰나:** AI가 파일을 잘못 지웠거나, 내용이 잘못 바뀌었을 때.

**무슨 일이 일어나나:**
- 최근 백업 목록이 나타남
- 번호를 골라서 되살리기

**예시 출력:**
```
📁 최근 백업 목록:
1. readme.txt — 2026-06-28 14:32:11
2. config.json — 2026-06-28 13:15:44
3. index.js — 2026-06-27 18:02:30

몇 번 파일을 되살릴까요? (번호 입력):
```

> ⚠️ **주의:** 폴더 통째는 차단(🛑)되므로 백업이 없습니다. 파일 단위 백업만 복구 가능합니다.
>
> 💾 **백업 보관 기간:** 백업은 **최근 100개 + 30일**까지 보관되고, 그보다 오래된 것은 새 백업이 뜰 때 자동 정리됩니다. 되돌리기는 이 범위 안에서 가능해요. (조정: `~/.sodamharness/safety-rules.json`의 `backupPolicy`)

---

### `/sodam-harness:trust` — 12시간 동안 안 묻기

**언제 쓰나:** 같은 작업에 매번 "정말 할까요?"가 떠서 귀찮을 때.

**무슨 일이 일어나나:**
- "이 폴더에서 이 작업은 안 물어봐도 돼"를 등록 (폴더 + 작업종류 기준)
- **차단(🛑)과 백업(💾)은 계속 유지됩니다.** 확인 질문만 생략.
- **12시간 후 자동 소멸.** 세션(대화)을 새로 시작해도 유지됩니다 — 같은 폴더에서 같은 작업을 반복한다면 다시 물어보지 않아요.

> ⚠️ **주의:** trust는 확인 질문을 줄이는 것이지, 차단과 백업을 없애는 게 아닙니다.

---

### `/sodam-harness:wizard` — 확인창 빈도 맞춤 설정

**언제 쓰나:** 확인창("정말 할까요?")이 너무 자주 뜨거나, 반대로 지금 설정이 어떤지 바꾸고 싶을 때.

**무슨 일이 일어나나:**
- 질문 하나를 물어봅니다: "확인창이 얼마나 자주 뜨길 원하세요?" (A/B/C 중 선택)
- 답변에 따라 `~/.sodamharness/profile.json`에 설정을 저장합니다.

| 선택 | 등급 | 실제 동작 |
|---|---|---|
| A) 항상 확인 | L1 (기본값) | 지금까지와 **100% 동일** — 아무것도 안 바뀜 |
| B) 같은 폴더 반복 작업은 하루 동안 안 물어봄 | L2 | `/sodam-harness:trust`의 신뢰 유지 기간이 12시간 → **24시간**으로 늘어남 |
| C) 되돌리기 가능한 작업(백업됨)은 최대한 안 물어봄 | L3 | 위험(risky) 작업 중 **백업이 실제로 성공한 것**은 확인 없이 통과(백업은 계속 뜸) |

> 🔒 **어떤 설정을 골라도 절대 안 바뀌는 것(안전 바닥)**: 폴더 통째 삭제·시스템 삭제·`rm -rf` 같은 **치명 작업은 항상 차단**됩니다. `.env`·인증서 같은 **비밀 파일은 항상 다시 확인**합니다(백업이 안 되는 대상이라 되돌릴 수 없기 때문). 백업이 실패하면 **항상 차단**됩니다. 이 마법사는 오직 "확인창이 뜨는 빈도"만 조정하며, 안전장치 자체를 약하게 만들 수 없습니다.

**예시 출력:**
```
확인창이 얼마나 자주 뜨길 원하세요?
A) 항상 확인 (지금 기본이에요)
B) 같은 폴더 반복 작업은 하루 동안 안 물어봄
C) 되돌리기 가능한 작업(백업됨)은 최대한 안 물어봄
```
답변 후: `{"ok":true,"autonomy_level":"L2"}` 같은 결과가 나오면 성공입니다.

> 💡 언제든 `/sodam-harness:wizard`를 다시 실행하면 설정을 바꿀 수 있습니다.

---

### `/sodam-harness:log` — AI가 한 일 타임라인

**언제 쓰나:** "방금 AI가 뭘 했지?" 확인하고 싶을 때.

**무슨 일이 일어나나:**
- AI가 한 작업 목록을 시간 순서로 보여줌
- 파일 이름과 시각만 표시 (파일 내용은 표시 안 함)
- 비밀 파일(`.env` 등)은 이름도 마스킹(가림)

**예시 출력:**
```
📜 활동 기록 (최근 10건):
[2026-06-28 14:35] Write → readme.txt
[2026-06-28 14:33] Bash → (차단됨: 위험 명령)
[2026-06-28 14:32] Delete → old_file.txt (백업 완료)
[2026-06-28 14:30] Read → index.js
```

### 스킬 2개 (자동으로 도와주는 기능)

스킬은 명령처럼 직접 입력하는 것이 아니라, AI의 동작 방식을 자동으로 바꿔 줍니다.

| 이름 | 하는 일 | 어떻게 쓰나 |
|---|---|---|
| `beginner-tone` | AI의 모든 안내를 **쉬운 한국어 말투**로 바꿔 줌 | 보통 자동 적용. 어렵게 느껴지면 "쉽게 설명해 줘"라고 한마디 |
| `sodam-harness-self-check` | AI가 "다 됐어요" 하기 전에 **진짜 됐는지 스스로 점검**하고 증거를 보여줌 | 자동 적용 |

> 💡 위 명령과 스킬은 모두 **Claude Code 전용**입니다. Codex에서 쓰는 법은 위 **5-2번** 섹션을 보세요.

## 8. 문제·오류 대처 (증상 → 왜 → 지금 할 것)

> 더 자세한 진단은 입력칸에 **`/sodam-harness:fix`** 입력.

| 증상 | 왜 그런가 | 지금 할 것 |
|---|---|---|
| `/sodam-harness:...` 명령이 **안 떠요** | 설치 후 재시작을 안 함, 또는 설치가 안 됨 | Claude Code를 **완전히 껐다 켜기** → `/sodam-harness:` 확인. 그래도면 2번(설치) 다시 |
| 위험 작업인데 **안 멈춰요** | 플러그인이 꺼졌거나, 아직 모르는 위험 패턴 | Claude Code 껐다 켜기 → `/sodam-harness:status` |
| 너무 **자주 물어봐요** | 안전 위주 기본값 | 같은 작업이면 `/sodam-harness:trust` 로 12시간 동안 그만 묻기, 또는 `/sodam-harness:wizard`로 빈도 자체를 낮추기 |
| **"Node.js 없음"** 이라고 떠요 | 안전 훅이 Node.js로 동작 | `https://nodejs.org` 에서 **LTS** 설치 후 재시작 (위 1번 참고) |
| 실행 차단 경고 (SmartScreen/Gatekeeper) | 처음 보는 프로그램이라 OS가 한 번 물어봄 | 정상적으로 받은 파일이면 "실행 허용" 선택 |
| 실수로 **파일을 지웠어요** | — | `/sodam-harness:undo` (목록에서 고르기) |
| 실수로 **파일을 다른 곳으로 옮겼어요** | 이동도 삭제와 같이 백업됩니다 | `/sodam-harness:undo` (목록에서 고르기) |
| **폴더를 지웠어요** | 폴더 삭제는 차단(🛑)되므로 이 경우는 거의 없음 | 혹시라도 지워졌다면 `/sodam-harness:undo` 확인 (폴더 자체 복구는 불가) |
| 백업 폴더 오류 (권한·용량) | 디스크 가득참 또는 권한 문제 | 공간 확보 후 재시도. 백업 못 하면 위험 작업은 **자동 중단**됩니다 |
| 한글이 **깨져요** | 터미널 인코딩 문제 | 보통 안 깨짐(Node.js). 그래도 깨지면 `/sodam-harness:fix` 입력 |
| 설명이 **어려워요** | 쉬운 말투 스킬이 항상 자동 적용되지 않을 수 있음 | AI에게 **"쉽게 설명해 줘"** 라고 한마디 |
| 옛 이름(`/install` 등)·중복 명령이 떠요 | 이전 설치 잔재 | Claude Code **완전 재시작**. 그래도면 재설치 |
| Claude Code 자체가 **안 켜져요** | Claude Code 또는 Node.js 문제 | `node --version` 으로 Node.js 확인 → 없으면 설치. Claude Code 재설치 고려 |
| **백업이 너무 많이 쌓여요** | 자주 작업하면 백업이 쌓임 | `.sodamharness/backups/` 폴더에서 오래된 것을 수동으로 삭제해도 됩니다 |
| **마법사로 설정한 게 이상하게 동작해요** | `profile.json`이 깨졌거나 손상됨 | 자동으로 가장 안전한 기본값(L1, "항상 확인")으로 되돌아갑니다. `/sodam-harness:wizard`를 다시 실행해 재설정하세요 |

## 9. 제거(삭제) 방법

### 플러그인 제거

**방법 A — 화면으로:**
1. Claude Code에서 **`/plugin`** 입력.
2. 플러그인 목록에서 **SoDamHarness** 를 찾아 **제거(Uninstall)** 클릭.
3. Claude Code를 **껐다 켭니다.**

**방법 B — 명령으로:**
```
claude plugin uninstall sodam-harness@sodamharness-marketplace
```

### 백업 데이터 삭제 (선택)

플러그인을 지워도 백업 폴더는 자동으로 남습니다. 백업까지 지우려면:

- **윈도우:** 탐색기에서 `C:\Users\내이름\.sodamharness\` 폴더를 찾아 **삭제**.
- **맥:** Finder에서 `/Users/내이름/.sodamharness/` 삭제. (숨긴 폴더이므로 **Cmd + Shift + .** 으로 숨긴 파일 표시 후 삭제)

> 💡 백업을 남겨두고 싶으면 플러그인만 제거하고 `.sodamharness/` 폴더는 그대로 두어도 됩니다.

## 10. 자주 묻는 질문 (FAQ)

---

**Q1. 정말 안전한가요? "100% 안전"이라고 써 주세요.**

A. 솔직하게 말씀드립니다. **흔한 위험은 막아 주지만 모든 경우를 100% 막진 못합니다.** "안전벨트"이지 "방탄막"이 아닙니다. 예상치 못한 새로운 위험 패턴은 놓칠 수 있습니다. 진짜 중요한 자료는 이 도구만 믿지 말고 별도로 백업하세요. "100% 안전"을 보장하는 소프트웨어는 세상에 없습니다.

---

**Q2. 제 비밀번호나 토큰을 몰래 보나요?**

A. 아니요. SoDamHarness는 `.env`, `auth.json`, 인증서(`*.pem`, `*.key`) 등 민감한 파일에 **접근하지 않습니다.** 활동 로그에도 파일 내용은 기록하지 않고, 데이터를 외부로 보내지 않습니다. 백업에도 비밀 파일은 **절대 포함하지 않습니다.**

---

**Q3. 인터넷이 필요한가요?**

A. 설치할 때 한 번만 필요합니다. 그 이후 안전 기능 자체는 **인터넷 없이 내 컴퓨터 안에서만** 동작합니다.

---

**Q4. 이거 바이러스 아닌가요? 믿어도 되나요?**

A. SoDamHarness는 오픈소스(Apache 2.0)이며 코드를 공개합니다. GitHub에서 코드를 직접 확인할 수 있습니다. 인터넷에 아무 데이터도 보내지 않으며, 내 컴퓨터 안에서만 동작합니다. 걱정되신다면 IT 전문가에게 코드를 보여드리고 확인 받으시는 것을 권장합니다. 공식 출처(SoDam AI Studio GitHub 페이지 또는 개발자로부터 직접)로 받았다면 안심하고 설치해도 됩니다. 다만 "무조건 믿어도 된다"고 보장하지는 않습니다 — 출처가 불분명하다면 조심하시고, 오픈소스를 직접 확인하는 것이 가장 안전합니다.

---

**Q5. 실수로 중요한 파일을 지웠어요. 어떻게 해요?**

A. `/sodam-harness:undo` 를 입력하면 백업 목록이 나옵니다. 번호를 골라서 되살리세요. 단, **백업은 작업 직전에 자동으로 저장**되므로, SoDamHarness가 설치되기 전이나 백업에 실패한 경우에는 되살리지 못할 수 있습니다. 중요한 자료는 별도 백업을 꼭 하세요.

---

**Q6. 실수로 폴더를 통째로 지웠는데 복구되나요?**

A. 안타깝지만 **폴더 통째 백업은 하지 않습니다**(폴더 안에 파일이 수백 개일 수도 있어서). 대신 SoDamHarness는 폴더 통째 삭제 자체를 **아예 차단**하기 때문에, 안전벨트가 켜져 있었다면 애초에 이런 일이 일어나지 않았어야 합니다. 폴더 **안의 개별 파일**(삭제 전 백업됨)은 `/sodam-harness:undo`로 복구할 수 있습니다. 만약 폴더가 실제로 지워졌다면 그 순간 플러그인이 꺼져 있었을 가능성이 높으니 `/sodam-harness:status`로 점검하세요.

---

**Q7. 왜 Node.js가 필요한가요? 저는 코딩을 안 해요.**

A. SoDamHarness의 안전 기능(경비원·백업·기록)이 Node.js라는 프로그램으로 만들어져 있기 때문입니다. Node.js는 이 도구를 동작시키는 엔진 역할입니다. 코딩을 전혀 몰라도 설치만 하면 되고, 한 번 설치하면 다시 신경 쓸 일이 없습니다. (완전 무료이며, 설치에 3~5분 정도 걸립니다.)

---

**Q8. 배터리나 컴퓨터 속도에 영향을 주나요?**

A. 거의 없습니다. SoDamHarness는 AI가 작업을 할 때만 잠깐 실행되고, 평소엔 대기 상태입니다. 파일 하나 백업하는 데 걸리는 시간은 1초 미만이며, CPU·메모리 사용량도 매우 적습니다. 컴퓨터 속도나 배터리에서 체감할 만한 변화는 없습니다.

---

**Q9. 맥(Mac)에서도 되나요?**

A. 같은 코드로 동작하도록 만들었지만, 현재 **윈도우에서만 실제 검증**했습니다. 맥은 미검증 상태입니다. 맥에서 써 보시고 문제가 있으면 개발자에게 알려 주시면 도움이 됩니다.

---

**Q10. Codex(코덱스)에서도 같은 보호가 되나요?**

A. 아니요. 차단·백업·되돌리기는 **Claude Code 전용**입니다. Codex에서는 Codex 자체 승인 창과 샌드박스로 대신합니다. 자세한 내용은 위 **5-2번** 섹션을 보세요.

---

**Q11. "자동 승인(YOLO) 모드"가 뭔가요?**

A. Claude Code의 설정 중 하나로, 모든 작업에 "예"를 자동으로 눌러 주는 모드입니다("YOLO 모드"라고도 부릅니다). 이 모드에서는 SoDamHarness의 "정말 할까요?" 확인 창이 생략될 수 있습니다. **그래도 백업은 항상 됩니다.** 치명적인 작업(폴더 통째 삭제 등)의 완전 차단도 그대로 유지됩니다. 스스로 위험을 완전히 이해하는 숙련자가 아니라면 자동 승인 모드를 끄는 것을 권장합니다.

---

**Q12. 백업이 실패하면 어떻게 되나요?**

A. 디스크 용량 부족이나 권한 문제 등으로 SoDamHarness가 백업을 만들지 못하면, 그 위험한 작업은 **자동으로 취소**됩니다. 백업이 안 됐는데 삭제·덮어쓰기가 그대로 진행되는 일은 없습니다. 무엇이 잘못됐는지 안내 메시지가 나타납니다 — "백업이 안 되면 작업도 안 한다"는 안전 최우선 설계입니다.

---

**Q13. 안전벨트가 진짜로 작동하는지 어떻게 확인하나요?**

A. `/sodam-harness:status` 를 입력하면 각 구성 요소의 상태를 점검해 알려줍니다. 직접 체험해 보고 싶다면 **버려도 되는 빈 폴더**에서 AI에게 "이 폴더 통째로 지워 줘"라고 시켜 보세요. 안전벨트가 작동 중이면 즉시 차단 메시지가 나타납니다. 단계별 절차는 위 **3번(빠른 시작)** 섹션을 참고하세요.

---

**Q14. Claude Code 없이 써도 되나요? 다른 AI 도구(Cursor·Gemini 등)에서도 되나요?**

A. 자동 차단·백업·되돌리기 같은 핵심 안전 기능은 Claude Code의 **플러그인(훅) 구조**를 그대로 사용하기 때문에 Claude Code 없이는 동작하지 않고, Cursor·GitHub Copilot·Gemini 등 다른 도구에서도 이 핵심 기능은 작동하지 않습니다. 다만 플러그인 폴더 안의 `AGENTS.md`(쉬운 말투 지침)는 다른 프로젝트 폴더에 복사해 두면 일부 AI 도구가 인식할 수 있습니다 — 단, 이건 "말투 안내"일 뿐 **차단·백업 기능은 아닙니다.**

---

**Q15. 경고·오류 메시지를 이해하지 못하면 어떻게 하나요?**

A. 메시지를 그대로 복사해서 Claude Code에 붙여넣고 "이 메시지가 나왔는데 무슨 뜻이고 어떻게 해야 해?"라고 물어보세요. AI가 쉬운 말로 설명해 줍니다. `/sodam-harness:fix` 명령을 입력해도 흔한 문제들을 단계별로 안내받을 수 있습니다.

---

**Q16. 백업 파일이 너무 많이 쌓이면 어떻게 하나요?**

A. 대부분 **자동으로 정리**됩니다. 백업은 **최근 100개 + 30일**까지 보관되고, 그보다 오래된 것은 새 백업이 생길 때 자동으로 정리됩니다(한 번에 최대 200개). 그래도 더 줄이고 싶으면 `~/.sodamharness/backups/` 폴더(윈도우: `C:\Users\내이름\.sodamharness\backups\`)에서 오래된 `.bak` 파일을 직접 삭제해도 됩니다. 보관 기준은 `~/.sodamharness/safety-rules.json`의 `backupPolicy`(keepN·keepDays)로 조정할 수 있습니다.

---

**Q17. 제 데이터가 SoDam AI Studio나 다른 외부로 전송되나요?**

A. 아니요. 파일·파일 이름·활동 기록 등 **어떤 데이터도 SoDam AI Studio나 그 어떤 외부 서버로도 전송되지 않습니다.** 모든 것이 내 컴퓨터 안에만 저장됩니다. 자세한 데이터 흐름은 위 **5-1번** 섹션의 다이어그램을 참고하세요.

---

**Q18. 팀원·회사에서 같이 써도 되나요? 수정해서 배포하거나 팔아도 되나요?**

A. 네, 전부 가능합니다. Apache 2.0 라이선스이므로 **상업적 사용·회사 도입·팀 사용·수정·재배포·판매**가 모두 허용됩니다. 다만 반드시: 라이선스 고지 보존, 저작권 고지 보존, 변경 사항 명시, NOTICE 파일 동봉(있는 경우)을 해야 합니다. 자세한 내용은 아래 **11번** 섹션과 **LICENSE 파일**을 참고하세요.

---

**Q19. 안전벨트가 너무 자주 물어봐서 귀찮아요.**

A. `/sodam-harness:trust` 명령으로 "이 폴더에서 이 작업은 안 물어봐도 돼"라고 등록하면 됩니다. 폴더+작업종류 기준으로 12시간 동안 유지되며, 대화(세션)를 새로 시작해도 초기화되지 않습니다. 확인창 자체의 빈도를 더 근본적으로 조정하고 싶다면 `/sodam-harness:wizard`를 써 보세요. 또한 Claude Code의 자동 승인(YOLO) 모드를 켜면 확인 창이 생략됩니다 (백업은 유지됩니다).

---

**Q20. `/sodam-harness:trust` 를 하면 차단도 해제되나요?**

A. 아닙니다. trust는 **"정말 할까요?"라는 확인 질문만 생략**합니다. 차단(🛑)과 백업(💾)은 trust 이후에도 계속 유지됩니다.

---

**Q21. `/sodam-harness:wizard`로 확인창을 줄이면 덜 안전해지나요?**

A. 아닙니다. 마법사는 **오직 "정말 할까요?" 확인 질문이 뜨는 빈도만** 조정합니다. 폴더 통째 삭제·시스템 삭제 같은 **치명 작업 차단은 어떤 설정에서도 항상 그대로**이고, 비밀번호·토큰 같은 **비밀 파일은 항상 다시 확인**하며, 백업이 실패하면 **항상 차단**됩니다. "확인을 덜 받는다"와 "덜 안전해진다"는 다릅니다 — 안전장치 자체는 줄지 않습니다.

---

**Q22. "210개 셀프테스트 통과"가 무슨 뜻인가요?**

A. SoDamHarness 개발 과정에서 210가지 테스트 케이스(위험 차단·백업·되돌리기·경계 상황·적대적 우회 시도·파일 이동/이름변경 보호·git commit 비밀파일 검사·맞춤 마법사 레벨별 동작 등)를 직접 실행해서 모두 통과했다는 의미입니다. "기본 기능이 의도대로 동작한다"는 것을 확인한 것이지, "모든 상황에서 100% 완벽"하다는 의미는 아닙니다.

### 2026-08-20~21 — 적대적 우회탐지 18건 차단 + 되돌리기(undo) 정직성 결함 수정 (안전 강화, 완화 0)
- **PowerShell 우회 경로 다수 차단**: 파일 내용을 조용히 비우는 `Clear-Content`/`Clear-Item`(짧은 별칭 `clc`), 기존 파일을 덮어쓰는 `New-Item -Force`(별칭 `ni -Force`), 원본을 백업 없이 이동·복사하는 `Move-Item`/`Copy-Item`의 짧은 별칭(`mi`/`cpi`)이 지금까지 감시망을 통과하고 있던 것을 찾아 막았습니다.
- **폴더·드라이브 통째 파괴 명령 신규 차단**: 폴더 전체를 미러링하며 목적지 내용을 지우는 `robocopy /MIR`·`/PURGE`, 드라이브·파티션 자체를 지우거나 포맷하는 `Format-Volume`/`Clear-Disk`/`Remove-Partition`/`Initialize-Disk`, `.NET`으로 파일 내용을 직접 덮어쓰는 `[System.IO.File]::WriteAllText`/`WriteAllBytes`, 대량 복사·구버전 도구인 `xcopy`를 새로 감시 대상에 추가했습니다. 드라이브·파티션 파괴는 **되돌릴 수 없는 재앙 등급(즉시 차단)**으로 분류했습니다.
- **가장 근본적인 사각지대 차단 — "내용을 못 읽는 명령은 위험하게 취급"**: `powershell -EncodedCommand`(명령을 base64로 숨기는 방식)·`Invoke-Expression`/`iex`·bash `eval`처럼, 안전벨트가 **명령 내용 자체를 읽을 수 없게 만드는** 실행 방식은 무엇을 하는지 알 수 없다는 이유만으로 위험하게 처리하도록 만들었습니다. 이건 특정 명령 하나가 아니라 "감시를 피해가는 방식" 자체를 막는 조치입니다.
- **되돌리기(undo)가 부분 실패를 "완전 실패"로 잘못 보고하던 결함 수정**: 여러 파일을 한 번에 되돌릴 때, 그중 한 파일의 복구만 실패해도(예: 그 사이 폴더가 사라짐) **이미 성공적으로 복구된 나머지 파일까지 포함해 "0개 복구됨"으로 잘못 보고**하던 결함을 발견해 고쳤습니다. 지금은 성공한 파일 수를 정확히 세고, 실패한 파일만 따로 "이건 못 되돌렸어요"라고 정직하게 알려 줍니다. 실제로 파일이 사라지는 결함이 아니라 **보고 문구의 정확성 결함**이었지만, "되돌리기"라는 이 제품의 핵심 신뢰와 직결되는 부분이라 우선순위 높게 처리했습니다.
