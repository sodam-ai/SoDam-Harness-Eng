## 시나리오 A — 골든 패스 (잘 풀리는 경우)

| 단계 | 민지가 하는 것 | 기대 동작 | ❓발견된 구멍 |
|---|---|---|---|
| A1 설치 | SoDamHarness를 깐다 | 클릭으로 설치 | ❓**설치 진입점이 불명** — 민지가 "마켓플레이스"를 **어떻게 여는지** 모른다(슬래시 명령? 설정 메뉴?) |
| A2 첫 인사 | Claude Code를 연다 | AI가 쉬운 한국어로 인사·다음 단계 안내 | ❓AI 말투 규칙(AGENTS.md)이 **민지의 기존 프로젝트 규칙과 충돌/덮어쓰기** 될 수 있다 |
| A3 작업 지시 | "소개 웹페이지 만들어줘" | AI가 파일 생성 | ✅ (안전 작업) |
| A4 위험 작업 | "이전 파일 다 지워줘" | 실행 **전에** 멈추고 "정말 할까요? 먼저 백업할게요" | ❓이 **확인 창 문구를 우리가 한국어로 바꿀 수 있나?**(권한 프롬프트는 Claude Code가 띄움) |
| A5 백업·실행 | "응" | 백업 후 삭제 | ❓**어느 폴더까지** 보호·백업 대상인가(작업 폴더? 컴퓨터 전체?) |
| A6 후회 | "아 실수했어, 되돌려" | 백업에서 복구 | ❓민지가 **`되돌리기` 명령을 기억** 못 함 → AI가 먼저 제안해야 |
| A7 막힘 | "뭔가 안 돼" | 자가진단이 상태+다음 행동 안내 | ✅ |

## 시나리오 B — 실패·엣지 (현실에서 자주 터지는 경우)

| 상황 | 무슨 일이 나나 | ❓발견된 구멍 |
|---|---|---|
| B1 Node.js 없음 | 안전 훅(.mjs)이 안 돈다 → **사고 방지 기능이 침묵** | ❓**Node.js 사전 점검·한국어 안내**가 PRD에 없음. (Claude Code가 Node 기반이라 보통 있음 — *추정, 확인 필요*) |
| B2 네트워크 차단/오프라인 | 설치 자체가 안 됨 | ❓오프라인 안내 누락(경미) |
| B3 기존 hooks 보유 사용자 | 우리 훅과 **충돌** 가능 | ❓**기존 hooks/설정과의 병합·충돌 정책**이 없음(사용자 핵심 가치=기존 보존과 직결) |
| B4 위험 폴더에서 시작 | 시스템·홈 광역 경로에서 위험 작업 | ❓**작업 범위(workspace) 정의** 없음 → 보호 경계 모호 |
| B5 차단이 안 뜸 | 우리가 정의 못 한 위험 패턴은 통과 | ✅ 이미 한계 명시(§8.8) — 단 Troubleshooting에 반영 필요 |
| B6 백업 폴더 권한/용량 문제 | 백업 실패 시 위험 작업이 그대로? | ❓**백업 실패 시 동작**(=위험 작업도 중단?) 미정 → 안전 기본=중단 |

## 발견 정리 → 강력 추천 (가장 안전·현실적)

| # | 발견(미결) | 분류 | 강력 추천 처리 방향 |
|---|---|---|---|
| H1 | 설치 진입점 불명(A1) | 결정 필요 | README에 **Claude Code 플러그인 추가 절차를 클릭 단위**로 + 화면 예시. *정확한 명령/메뉴는 구현 시 확인.* |
| H2 | 기존 AGENTS.md·hooks 충돌(A2·B3) | **위험** | **덮어쓰지 않고 "추가"만**, 충돌 감지 시 사용자에게 알림·선택권. (사용자 핵심 가치=기존 보존) → 04 DO NOT·§데이터에 반영 |
| H3 | 확인창 문구 한국어화 한계(A4) | 확인 필요 | **훅이 주는 "사유 메시지"는 한국어로**(우리 제어 범위). Claude Code **권한 프롬프트 자체** 문구 커스터마이즈 범위는 *구현 시 확인* → README에 한계 안내 |
| H4 | 보호 범위(workspace) 모호(A5·B4) | 결정 필요 | ~~현재 작업 폴더 안만 보호~~ → **2026-06-21 실측 변경**: '작업폴더 밖 거부'는 정상 작업까지 막는 과잉차단이라 폐기 → **민감 위치(시스템·홈·자격증명·드라이브 루트)만 차단** + 폴더 통째/재귀 삭제 deny |
| H5 | 되돌리기 인지(A6) | 누락 | 사고 직후 AI가 **"되돌리려면 이렇게 하세요"를 먼저 안내**(수동 기억 의존 X) |
| H6 | Node.js 사전 점검(B1) | 누락 | 자가진단(status)이 **Node.js 유무 점검**, 없으면 한국어 설치 안내. (있음=추정→점검으로 확실히) |
| H7 | 백업 실패 시 동작(B6) | 결정 필요 | **안전 기본=백업 못 뜨면 위험 작업도 중단**(fail-safe). 사용자에게 사유 안내 |

> 위 H1~H7은 01_PRD §13(미결)과 04 DO NOT/데이터 모델에 반영한다. 대부분 **실제 구현 시 한 번의 확인**으로 닫히는 항목이며, 본래 목적(초보자 안전·쉬움)을 강화한다.

## 결론
- 골든 패스는 성립하지만, **설치 진입점·기존 설정 충돌·확인창 한국어·보호 범위·백업 실패 처리**가 **구현 전 닫아야 할 진짜 구멍**이다.
- 가장 위험한 것은 **H2(기존 설정 덮어쓰기)**와 **H3(확인창을 초보자가 이해 못 함)** — 둘 다 "안전·쉬움" 본질을 직접 위협하므로 Phase 1 설계 단계에서 우선 해결.
