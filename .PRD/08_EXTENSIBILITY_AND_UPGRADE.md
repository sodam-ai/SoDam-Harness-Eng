# SoDamHarness — 확장·업그레이드 설계 ("추후 내가 원할 때 쉽게 고치기")

> 작성: 2026-06-21 · 목적: 사용자가 추후에도 안전 규칙·위험 패턴·정책을 **쉽고 안전하게** 추가/수정. 본래 목적(초보자 안전벨트, 제품 자신이 가장 안전) 유지.

## 1. 핵심 원칙 — "안전 판정을 코드 말고 '규칙 데이터'로"
- 위험 패턴·민감 위치·백업 정책·자율성 등급을 **데이터 파일**(`safety-rules.json`)에 둔다. 훅 코드는 "데이터 읽어 판정"만.
- **새 위험 패턴 추가 = 데이터 1줄**(코드 0). "이 명령도 막아줘" → 패턴 1개 추가.
- **왜**: 안전 도구일수록 코드 수술은 위험. 데이터 조정이면 회귀 위험 최소 + 비개발자도 자연어로 지시 가능.

## 2. 확장 지점
| 추가하고 싶은 것 | 고치는 곳 | 위험 | 비개발자 방법 |
|---|---|---|---|
| 새 위험 패턴(차단/확인) | `safety-rules` 데이터 | 낮음 | "이것도 막아줘" |
| 민감 위치 추가(OS별) | 민감경로 목록 데이터 | 낮음 | "이 폴더도 보호" |
| 백업 보존(기간·개수) | 정책 데이터 숫자 | 낮음 | "백업 30일로" |
| 새 도구(Codex 등) | 도구별 안전 매핑(config.toml↔hooks) | 보통 | "코덱스도 안전하게" |
| 말투/언어 | 공유 말투 스킬 | 낮음 | "영어도" |
| 자율성 등급 | 등급 데이터 | 낮음 | "더 자주 물어봐" |

## 3. 버전·기록
- semver(`plugin.json`) + `CHANGELOG.md`(한국어). 업그레이드 = `/plugin marketplace update`.
- 안전 규칙 변경은 **반드시 CHANGELOG에 "무엇을 왜"** (안전 변경 추적 의무).

## 5. 업그레이드 안전 규칙 (불변 — 안전 도구라 더 엄격)
- [ ] **안전 회귀검증 강화** — 규칙 한 줄 빠지면 사고. 업그레이드마다 "정해진 위험명령이 여전히 차단되나" 자동 점검.
- [ ] **fail-closed 유지** — 훅 오류·백업 실패 시 중단(통과 금지). 업그레이드가 이걸 못 깬다.
- [ ] **토큰·비밀 미접근 불변** — 어떤 업그레이드도 토큰/키 접근 추가 금지(자기보안 grep 0).
- [ ] **안전 단독 소유 보존** — Harness만 안전 차단. 업그레이드가 형제 영역 침범 금지([[SODAM_FAMILY_MAP]]).
- [ ] 모든 변경도 백업+확인·과장금지 동일.

## 6. 비개발자 UX
- "이 명령도 위험으로 막아줘" → AI가 `safety-rules` 데이터 1줄 추가 + "이렇게 막을게요" 미리보기 + 확인. 코드 0.

> **가족 공통 업그레이드 컨벤션**은 [[SODAM_FAMILY_MAP]]·SoDamContext `09` §9 참조(데이터화·semver·backlog·회귀검증·경계보존·번들 동시 업데이트).

## 한 줄
안전 도구의 "추후 쉽게 고침" = **위험 패턴을 데이터로** + 더 엄격한 회귀검증 + fail-closed 불변. 비개발자가 데이터 한 줄로 안전을 넓히되, 안전벨트 자체는 절대 약해지지 않게.
